# Jev Decisions 0.3.0

This release adds a local supervision layer: turn admission, an adaptive event router, challenge freshness, and a repeated failure control. It is shadow-first, makes no provider call of its own, and does not change who holds authority.

## What supervision adds

Hermes keeps working while supervision observes. A local classifier labels each turn `OFF`, `WATCH`, or `ON`. Only `WATCH` and `ON` turns are eligible for routing, and only a materially different event is forwarded. Routine and repeated equivalent state is suppressed before any provider call is made.

Four behaviors are adapted from the community project `keeltrace/hermes-jev`:

- Turn admission that never sits in the critical path.
- A local relevance router with semantic hysteresis and bounded batching.
- Challenge delivery that is valid only while the challenged state is current.
- Action and failure fingerprints with a provider independent local `REPLAN` control.

The new `jev_supervision` tool inspects and drives that layer. It answers from local state, needs no provider request, and never executes an action.

## Authority boundaries

Supervision is advisory by default. In the default `shadow` mode it records a control and reports it, but it changes nothing about tool execution.

Three settings exist:

- `off` disables supervision entirely.
- `shadow` (default) observes, routes, records, and reports, and never alters execution.
- `correct_next` and `precommit` enforce the local control lease: the exact repeated action that created a `REPLAN` control is blocked until a materially different action follows it or one retry is explicitly permitted.

Enforcement uses the documented `pre_tool_call` veto shape, `{"action": "block", "message": ...}`. There is still only one `pre_tool_call` owner in this plugin; the control lease is checked inside the existing callback, before the existing risk review, so a known repeated failure never pays a provider round trip.

Enforcement never authorizes anything. Approval and verification still live in the deterministic gateway, and the existing approval settings remain authoritative.

Set the mode and related thresholds through the environment:

- `JEV_SUPERVISION_MODE` (`off`, `shadow`, `correct_next`, `precommit`)
- `JEV_SUPERVISION_ENABLED`, `JEV_SUPERVISION_ADMISSION`
- `JEV_SUPERVISION_THRESHOLD`, `JEV_SUPERVISION_CHALLENGE_CONFIDENCE`
- `JEV_SUPERVISION_MAX_CALLS`, `JEV_SUPERVISION_REPLAN_AT`, `JEV_SUPERVISION_RETAIN`

Hook-driven supervision stays off until `JEV_ENABLE_HOOKS=1`, matching the existing automatic review posture. The `jev_supervision` tool works without that variable because it is an explicit call.

## Two efficiency changes

A repeated identical failure is fingerprinted and deduplicated locally. The first equivalent failure in a turn may be assessed remotely; later identical failures are not, and the failure that trips the local threshold creates the control without spending a provider call. A failing loop therefore stops generating provider requests instead of repeating them.

A challenge whose state version no longer matches the live turn is retained as local telemetry and never delivered as current advice.

## Deliberate differences from upstream

Three adaptations are intentional and worth stating plainly.

Admission is a local deterministic classifier rather than a remote assessment, because this plugin must not add provider latency to the ordinary turn path.

Semantic judgement stays in the existing `jev_workflow` surface. The router decides whether to ask, never what an answer means.

The upstream `ContextEngine` and automatic context deletion are not adopted in this release. Context management remains untouched.

## Known limits

Challenge delivery is explicit. A current challenge is attached to the `jev_workflow` response and is available through `jev_supervision` action `take_challenge`. This release does not inject a challenge into arbitrary tool results; that would require the separate `transform_tool_result` hook, which is not registered here.

Supervision state is turn scoped. A supervised turn is evicted after sixteen tracked turns if it is never closed with `end_turn`.

## Verification in this release

The tracked release tree runs 93 tests, including 33 unit tests for the supervision layer and 21 integration tests for the plugin wiring. The development checkout reports 98 because it also holds an untracked test for a private adapter, and that test is not part of this release.

Gates run before publication: the suite passes in a tracked-only clone, `compileall` is clean, the public secret scan is clean, `git diff --check` is clean, `hermes plugins doctor` reports version 0.3.0 with 7 tools and 3 hooks when pointed at that clone, and a fresh Hermes process called `jev_supervision` live and returned real output.

The integration tests assert that shadow mode returns no directive, that enforcing mode blocks only the exact repeated action, that a materially different action passes, that a permitted retry is consumed once, and that a stale challenge is recorded rather than delivered.
