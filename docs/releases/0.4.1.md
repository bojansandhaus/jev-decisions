# Jev Decisions 0.4.1

This release fixes three defects in 0.4.0, one of which could block your own tools. It also closes the local matching gap that 0.4.0 shipped as a documented limitation.

If you run an enforcing mode, upgrade. If you run the default `shadow` mode, the lesson gate could still have blocked a tool call by failing, so upgrade anyway.

## The lesson gate could block tools by failing

In Hermes, `pre_tool_call` is a fail-closed hook. A callback that raises an exception, or that runs past the callback timeout, is resolved as a block on the tool call rather than as no opinion. The 0.4.0 gate did file I/O on every tool call and had three ways to raise: the store directory was created outside the guarded block, a failed store write raised `OSError`, and malformed stored data could reach the tag handling.

On a read-only store directory, a full disk, or a hand-edited store file, that would have started vetoing tool calls instead of stepping aside.

The gate now abstains on any error and returns no opinion, and each failure is counted so it cannot look like a working guard:

```
jev_lessons action=stats
```

reports a `gate` block with a `count` and the last error. Seven tests cover the failure paths, including a corrupt store file and a deliberately hostile one, and the rule is asserted directly: a guard that cannot decide must not veto.

## Two processes could lose each other's lessons

The gateway, the CLI, and cron run as separate Hermes processes over one lesson store. The store is a single JSON document, and 0.4.0 wrote it with an unguarded read-modify-write, so the second writer silently dropped the first one's lesson.

Writes now take an advisory `flock` and reload under the lock. This is tested by writing from two stores over one file, and the test is load-bearing: with the reload suppressed, three lessons become two.

## The local match reaches paraphrases

0.4.0 matched on exact words, so a `kick` lesson stopped an action only when the two read nearly the same, and missed any rephrasing. `clear out the temporary decision folder with a recursive delete` did not match a lesson written as `rm -rf /tmp/jevs-decision-store`.

The match now runs over canonical words. Different ways of naming the same action collapse onto one token: `remove`, `delete`, `wipe`, and `clear` become `delete`; `tmp` and `temporary` become `temporary`; `dir` and `folder` become `directory`; `-rf` becomes `recursive`. Paths and flags are split, so `/tmp/jevs-decision-store` contributes the same words as the prose version, and the tool envelope (`terminal`, `command`) is dropped so it cannot dilute the score.

That rephrasing now stops the action locally, with no provider call. The reach is measured rather than asserted: over the calibration pairs in `tests/test_lessons.py`, the paraphrases that must fire score 0.57 to 1.00 and the actions that must not fire score at most 0.14. The floor sits at 0.40, inside that band and biased toward precision, because a wrong kick blocks real work.

A second, independent gate applies: at least three canonical words in common. Without it a one word lesson could reach the floor through the containment term alone against a long action, which is the cheapest way to block something by accident.

## What is still not caught

Reach is bounded by a hand written table, so an unbounded rephrasing that shares no canonical word with the lesson still slips past the local gate. `get rid of the scratch area used for the decisions work` is not caught by that same delete lesson, and a test pins that miss so the boundary cannot be claimed as closed when it is not.

That residual is deliberate. A local hard stop may not call a provider, so the only reach it can have is reach that can be written down and reviewed line by line. The semantic judgement stays with Jev through an explicit review. The canonical table is a small list of claims about meaning, not a language model, and it is meant to be edited.

## Authority is unchanged

Nothing here widens what a lesson may do. Enforcement is still opt in and global, `shadow` is still the default, and in shadow a kick stops nothing while the match is recorded to the ledger as `lesson_would_kick` with no catch counted. A test asserts that the wider reach does not widen authority: the paraphrased action that is blocked in an enforcing mode still stops nothing in shadow.

## Verification

- 171 tests in the tracked tree, all passing, up from 154 in 0.4.0.
- The paraphrase tests fail against the 0.4.0 matcher and pass against this one, so the fix is load-bearing rather than a threshold nudge.
- The concurrency test fails with the reload suppressed, so the lock fix is load-bearing too.
- `hermes plugins doctor` on a tracked-only clone: version 0.4.1, 8 tools, 3 hooks.
- Public scan clean, no private paths or secret-like content.
